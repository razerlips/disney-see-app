# disney-see-app

東京ディズニーシーの **ショー時間** と **待ち時間** を一目で見る自分用アプリ 🌋🎭
待ち時間まわりは tdr-wait-app をもとにして、シーだけに絞っています（tdr-wait-app 本体には手を加えていません）。

## できること

### 🎭 ショータブ（最初に開くタブ）

- いちばん上に **「次のショー」**：上演中・これからの回を 3 つ、「あと 25 分」つきで大きく表示（30 分を切るとピンク）
- その下に一覧。切り替えできます
  - **時間順**：全ショーの回を 1 本の時刻表に（終わった回は隠す。「終わった回」にチェックで表示し、「いま」の線が入る）
  - **ショー別**：ショーごとのカードに時間のチップ。次の回は青く塗り、終わった回は取り消し線
- 「あと何分」「上演中」「終了」は 30 秒ごとに自動で切り替わります（通信はしない）
- ☆でお気に入り（ショー別で登録）→「★だけ」で絞り込み
- **✏️ ショー時間を入力**：公式アプリ・公式サイトで見た時間を、その場でスマホから入れられます
  - ショーは一覧から選ぶ（ThemeParks.wiki のショー一覧）か「その他」で名前を入力
  - 時間は `10:30 13:00 15:30-15:55` のように区切って入力（`1030`・`10時30分`・全角も OK。終わりの時刻を書いた回は「上演中」も出る）
  - 入れた時間はそのスマホのブラウザに保存（ほかのスマホには引き継がれない）。前日より前の分は自動で消えます
  - 「公式の今日のスケジュール ↗」から公式サイトのその日のショー一覧を開けます（リンクだけで、自動取得はしません）
- 時間のマーク：📱 このスマホで入力 ／ 🖊️ `data/show-times.json` に登録 ／ 🔄 ThemeParks.wiki から自動取得。同じショーが重なったら 📱 → 🖊️ → 🔄 の順で優先

### 🎢 待ち時間タブ

tdr-wait-app と同じです（シーだけ）。待ち時間・運営状況・エリア、DPA の販売状況バッジ、シングルライダーのバッジ、訪問日の運営予定時間、並び替え（長押しドラッグのカスタム順も）、お気に入り。
細かい決まりごと（DPA の価格表、除外リスト、運営予定時間の登録など）は下の各章と tdr-wait-app の README を参照してください。

お気に入り・並び順・入力したショー時間は、使っているブラウザに保存されます。

## ショー時間について（大事）

tdr-wait-app でも一度ショータブを作り、2026-10-02 に「公開データから公演時刻が取れず実用性が低い」として削除しています。今回はその反省から、**スマホから直接入力できる**ようにしました。

| 元 | 中身 | 状況 |
| --- | --- | --- |
| ThemeParks.wiki | シーのショー一覧（11 件）と、あれば公演時刻 | 一覧は取れる。**東京の公演時刻は 2026-10-01・2026-11-23 の確認では 0 件**。将来載ったら自動で表示される |
| 公式サイト | 正確な公演時刻 | 利用規約で自動取得が禁止・機械的なアクセスも拒否される → リンクだけ |
| スマホから入力 | 公式で見た時間 | 実質の主役 📱 |
| `data/show-times.json` | 公式で見た時間（サーバー側） | ほかの端末でも見たいときに |

推測・別の日からの流用はしません。どこにも時間がないショーは出しません。

### data/show-times.json の書き方

```json
"2026-12-05": {
  "sea": [
    { "name": "ビリーヴ！～シー・オブ・ドリームス～", "en": "Believe! Sea of Dreams", "area": "メディテレーニアンハーバー", "times": ["19:15"], "note": "鑑賞エリアは抽選" },
    { "name": "ショーの名前", "times": [{ "start": "10:15", "end": "10:45" }, "13:40"] }
  ]
}
```

時刻は日本時間。`en`（英語名）を書くと ThemeParks.wiki の同じショーと確実に重なります。動作確認で別の日を見たいときは `SHOWS_DATE=2026-12-05 npm start`。
ThemeParks.wiki に時刻が載ったかは、Actions の「API check」→「ショー時間が ThemeParks.wiki に載っているか」（`node scripts/check-shows.mjs`）で確認できます（パークの営業中に実行）。

## 動かし方（はじめての人向け）

必要なのは **Node.js（バージョン 18 以上）** だけです。追加のインストール（`npm install`）は要りません。

1. Node.js を入れる：<https://nodejs.org/ja> から「LTS」と書かれた方をダウンロードしてインストール
2. ターミナル（Mac なら「ターミナル」、Windows なら「PowerShell」）を開いて、このフォルダに移動
   ```sh
   cd disney-see-app
   ```
3. 起動する
   ```sh
   npm start
   ```
4. 「起動しました 👉 http://localhost:3000」と出たら、そのアドレスをブラウザで開く
5. 終わるときはターミナルで `Ctrl + C`

### ネットにつながっていなくても見た目を確認したいとき

```sh
npm run mock
```

`data/` フォルダのサンプルデータ（数字はでたらめです）で表示します。

### テスト

```sh
npm test
```

## スマホで使う（Render にデプロイ）

（まだデプロイしていません。tdr-wait-app と同じ手順で、このリポジトリを選べば動きます）

### 最初の設定（1 回だけ）

1. <https://render.com/> に GitHub アカウントでログイン
2. 「New」→「Web Service」→ このリポジトリ（`razerlips/disney-see-app`）を選ぶ
3. 次のように設定して「Deploy web service」

| 項目 | 値 |
| --- | --- |
| Language | Node |
| Branch | main |
| Root Directory | 空欄 |
| Build Command | `npm install` |
| Start Command | `npm start` |
| Region | Singapore（日本から近い。Oregon でも動く） |
| Instance Type | **Free**（初期値が有料プランのことがあるので必ず確認） |
| Environment Variables | なし（`MOCK` は入れない。入れるとサンプルデータになる） |

### 更新のしかた

`main` ブランチに変更が入ると、Render が自動で再デプロイします。何もしなくて OK です。

### 無料プランの注意

しばらくアクセスがないとサーバーが眠り、次に開いたとき表示まで 30 秒〜1 分かかります。
パークに着いたら最初に一度開いておくのがおすすめです。

### ホーム画面に追加する

- iPhone（Safari）：共有ボタン →「ホーム画面に追加」
- Android（Chrome）：右上の「︙」→「ホーム画面に追加」（または「アプリをインストール」）

専用アイコンで追加され、開くとブラウザのアドレスバーなしの全画面で表示されます。

## 行かない施設を一覧から外す（除外リスト）

`exclusions.js` に載っている施設は、通常一覧・並べ替え・お気に入りのみ表示のどれにも出ません（サーバー側で取り除くので、更新や再読み込みをしても出ません）。

- 運営状況が「休止・案内終了」かどうかとは関係なく、リストに載っている施設だけを外します
- 照合は ① データ元の ID ② 英語名 ③ 日本語名 の順。名前は空白・記号・全角半角の違いだけを無視した完全一致なので、似た名前の別施設は外れません
- 施設を足したり戻したりするときは `exclusions.js` を編集します。ID は Actions の「API check」→「実データの施設 ID 一覧」のログで確認できます（各施設に「除外／表示」と、リストと実データの不一致が出ます）

## 待ち時間データについて

### 1. 公式 API はない

東京ディズニーリゾートは、待ち時間を外部から取得できる公式 API を公開していません。
公式アプリ・公式サイトの裏側の通信を直接使う方法は、利用規約上グレーで予告なく使えなくなるので候補から外しました。

### 2. 非公式 API の比較（2026-10-01 に GitHub Actions 上で実際に疎通テスト）

| | **Queue-Times.com** | **ThemeParks.wiki** | RopeDrop Planner | Park Queue Times |
| --- | --- | --- | --- | --- |
| ランド／シー対応 | ✅ 両方（ID 274 / 275） | ✅ 両方 | ❓ パーク指定が効かずフロリダのデータが返った | ✅（公称） |
| 待ち時間 | ✅ | ✅ | — | ✅（公称） |
| 運営状況 | 運営中／休止の 2 種類 | 運営中・一時運営中止・休止・改修 の 4 種類 | — | — |
| エリア情報 | ✅ あり | ❌ なし | — | — |
| 更新頻度 | 5 分ごと（実測：取得時点で 0〜4 分前） | 数分ごと（実測：0〜4 分前） | 5 分ごと（公称） | — |
| APIキー | 不要 | 不要 | 不要 | **必要**（無料登録） |
| 無料枠・規約 | 無料。「Powered by Queue-Times.com」とリンクの表示が条件 | 無料・オープンソース | 無料（公称） | 無料。クレジット表示が条件 |
| 疎通テスト（3 回実行） | ✅ 18/18 成功・約 140ms | ✅ 12/12 成功・約 15〜60ms | ❌ 0/18（タイムアウト・東京以外のデータ） | 未実施（キー登録が必要なため） |
| ブラウザから直接 | ×（CORS なし） | ○ | — | — |

### 3. 選んだもの

- **メイン：Queue-Times.com** … 両パークで全リクエスト成功。エリア情報があるのはここだけ。
- **予備：ThemeParks.wiki** … 同じく全リクエスト成功。メインが落ちたとき自動で切り替えます（そのときはエリアが「エリア情報なし」になります）。
- RopeDrop Planner は東京のデータが返ってこず、Park Queue Times は API キーが必要なので不採用。

アトラクション名・エリア名は英語で返ってくるので、`names-ja.js` と `sources.js` の対応表で日本語に置き換えています。表にない名前（新アトラクションや季節限定など）は英語のまま表示されるので、そのときは `names-ja.js` に 1 行足してください。Actions の「API check」のログに「日本語名なし」の一覧が出ます。
どちらも非公式データなので、数分の遅れやズレがあり得ます。正確な情報は公式アプリで確認してください。

### 疎通テストをもう一度やりたいとき

GitHub のリポジトリ画面 →「Actions」→「API check」→「Run workflow」で実行できます。
単体テスト・API 候補の比較・アプリを実データで起動して確認（メイン／予備の両方）までまとめて行います。
手元で試すなら `node scripts/check-apis.mjs`（比較）と `node scripts/smoke.mjs`（アプリの確認）です。

### しくみ（ざっくり）

```
ブラウザ（public/）  ──/api/waits?park=land──▶  server.js  ──▶  Queue-Times.com
                                                     │  失敗したら
                                                     └──────▶  ThemeParks.wiki
```

- **server.js**：画面ファイルを配り、待ち時間を代わりに取りに行くサーバー。同じパークへの問い合わせは 5 分間使い回して、相手サイトに負担をかけないようにしています。取れなかったときは前回のデータ（あれば）を「古いデータです」の印つきで返します。
- **sources.js**：2 つのデータ元から取ってきて、同じ形にそろえる部分。
- **public/**：画面（HTML／CSS／JavaScript）。
